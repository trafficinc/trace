# Install TRACE on a private host

TRACE defaults to a local SQLite database and owner-only local evidence/report storage. No database daemon, task queue or cloud account is needed. Optional PostgreSQL uses Django's standard backend; see [database transfer](postgresql.md). Supported application Python is **3.13**. Keep the complete source release: templates, static assets, scripts and lock files are part of the installation.

## Linux native installation

Example for **Debian 13**, with Python 3.13 supplied by the distribution. On other releases install that Python version using your distribution's supported packages or a prepared runtime; do not substitute an incompatible Python version.

```sh
sudo apt-get update
sudo apt-get install python3.13 python3.13-venv libpango-1.0-0 libpangoft2-1.0-0 libharfbuzz-subset0 fonts-dejavu-core nginx
# Unpack the reviewed release into a directory you own, then enter it.
umask 077
python3.13 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements/runtime.txt
python scripts/vendor_assets.py --check
python manage.py migrate --noinput
python manage.py configure_sqlite
python manage.py createsuperuser
python scripts/serve.py --development
```

Open `http://127.0.0.1:8000`. This developer path uses Waitress on loopback with local HTTP settings. `manage.py runserver 127.0.0.1:8000` remains a developer debugging option, never a production recommendation. `createsuperuser` prompts for a username and a validated password; no account or password is generated by startup. Create ordinary accounts in the application and grant engagement memberships explicitly.

Development commands default to development settings; WSGI/ASGI and the production startup command default to production. A `.env` file is **not** implicitly loaded by native commands.

## macOS

Use a local APFS directory outside cloud-synchronized folders. With Homebrew available:

```sh
brew install python@3.13 pango libffi
umask 077
python3.13 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements/runtime.txt
python scripts/vendor_assets.py --check
python manage.py migrate --noinput
python manage.py configure_sqlite
python manage.py createsuperuser
python scripts/serve.py --development
```

The PDF worker defaults to `/opt/homebrew/lib` on Apple Silicon when that directory exists. Intel installations can set `TRACE_REPORT_WEASYPRINT_DLL_DIRECTORIES=/usr/local/lib`. Evidence parser limits have the existing macOS-specific address-space-limit handling; pixel/side/CPU/wall-time bounds remain enforced.

## Windows developer computer

Use **WSL2**, because the evidence safeguards require POSIX descriptor-relative paths, no-follow file opens, advisory locks and resource-limited parser processes. Native Windows Python is not a substitute for these safeguards.

From an administrator PowerShell terminal:

```powershell
wsl --install -d Debian
wsl --set-default-version 2
wsl -d Debian
```

Inside WSL, use Debian 13 and the Linux commands above. Keep the release and `storage` under your Linux home directory, for example `~/trace`, rather than `/mnt/c`, OneDrive or a network drive. Open `http://localhost:8000` from the Windows browser after starting the server in WSL. Docker Desktop with WSL2 integration is the optional container path below. This keeps Windows development on the same file-security implementation as Linux.

## Native production service and HTTPS

Run on loopback behind a trusted HTTPS reverse proxy, on a private machine/LAN/VPN. The supplied proxy binds loopback by default; LAN listeners and firewall rules are explicit operator choices. Do not forward these ports from an internet router.

1. Create a dedicated unprivileged `trace` OS account. On Debian, an administrator can prepare ownership with:

```sh
sudo useradd --system --home-dir /var/lib/trace --shell /usr/sbin/nologin trace
sudo install -d -o trace -g trace -m 0700 /var/lib/trace /var/lib/trace-recovery /etc/trace
sudo install -d -o trace -g trace -m 0750 /opt/trace/releases
```

Put releases under `/opt/trace/releases`, with `/opt/trace/current` pointing at the selected release. Create `/var/lib/trace` owned by `trace`, mode `0700`, outside the source/static trees. Create `/etc/trace` mode `0700` for configuration, owned by the service account or readable only by its trusted service manager.
2. Copy `deploy/trace.env.example` to `/etc/trace/trace.env`, set the actual private hostname/origin and storage path, and generate the secret into that protected file. Do not paste credentials into command-line arguments or commit the file. `python -c "import secrets; print(secrets.token_urlsafe(64))"` generates a secret for private local entry; this is not a default application password.
After unpacking the reviewed release at `/opt/trace/releases/0.1.0`, prepare its virtualenv and initial configuration (adjust the version directory for each release):

```sh
sudo ln -s /opt/trace/releases/0.1.0 /opt/trace/current
sudo -u trace python3.13 -m venv /opt/trace/current/.venv
sudo -u trace /opt/trace/current/.venv/bin/python -m pip install -r /opt/trace/current/requirements/runtime.txt
sudo install -o trace -g trace -m 0600 deploy/trace.env.example /etc/trace/trace.env
```

Fill in the protected environment file before continuing; do not overwrite an existing installation's configuration or secret during updates.

3. As `trace`, load that environment explicitly and initialize the stopped service:

```sh
cd /opt/trace/current
set -a
. /etc/trace/trace.env
set +a
umask 077
. .venv/bin/activate
python manage.py migrate --noinput --settings=config.settings.production
python manage.py configure_sqlite --settings=config.settings.production
python manage.py collectstatic --noinput --settings=config.settings.production
python manage.py createsuperuser --settings=config.settings.production
python manage.py check --deploy --fail-level WARNING --settings=config.settings.production
```

4. Install a certificate and key from your trusted private CA. Clients must trust that CA; do not disable certificate verification. Adapt `deploy/nginx.conf` with the actual hostname/certificate paths. It belongs in nginx's `http` context. Disable stock/default nginx sites that listen on other addresses. Keep the supplied loopback listeners for local-only use. To allow a LAN, change nginx's listeners to one specific private interface IP, permit only intended client networks in the host firewall and DNS, and keep Waitress on loopback.
5. Install `deploy/trace.service` as `/etc/systemd/system/trace.service`, then run:

```sh
sudo nginx -t
sudo systemctl reload nginx
sudo systemctl daemon-reload
sudo systemctl enable --now trace
sudo systemctl status trace
```

The service uses the supported `python scripts/serve.py` WSGI entry point. It refuses unsafe bind addresses without `--allow-lan`, enforces production checks and refuses to start with pending migrations. It does not migrate or create accounts on boot. `TRACE_BIND_HOST` defaults to `127.0.0.1`, and `TRACE_BIND_PORT` to `8000`. Keep the backend socket reachable only by the trusted proxy. Waitress clears untrusted proxy headers; only `X-Forwarded-Proto` from the single configured `TRACE_PROXY_IP` is accepted. nginx overwrites that header, `Host` and forwarded client addresses; application throttling continues to use the WSGI peer rather than arbitrary client headers. Do not use `--url-scheme=https` to make plain HTTP appear secure.

Production enforces secure session/CSRF cookies, HTTPS redirects, explicit allowed hosts/origins and a private random secret. HSTS applies to the configured host for one year. It intentionally does not assert HTTPS for unrelated subdomains or opt private names into a public browser preload list; only Django recommendations W005/W021 are silenced for that documented policy. Other deployment checks remain active. `/health/` is the sole HTTPS-redirect exception, returning only readiness; it never exposes domain records. All other HTTP paths redirect to HTTPS.

## Docker Compose, still SQLite-first

The default Compose file starts **one application container**, with its SQLite/evidence/reports in the retained `tdt-data` volume. No database container or external service is required. The container listens on its isolated bridge; published host access defaults to `127.0.0.1:8000`. Keep a trusted host HTTPS proxy in front of that port.

Create a private Compose environment file from `deploy/compose.env.example`, fill in its secret and real hostname, then:

```sh
docker compose --env-file /private/path/trace-compose.env build
docker compose --env-file /private/path/trace-compose.env run --rm trace python manage.py migrate --noinput
docker compose --env-file /private/path/trace-compose.env run --rm trace python manage.py configure_sqlite
docker compose --env-file /private/path/trace-compose.env run --rm trace python manage.py createsuperuser
docker compose --env-file /private/path/trace-compose.env run --rm trace python manage.py check --deploy --fail-level WARNING
docker compose --env-file /private/path/trace-compose.env up -d --no-build
docker compose --env-file /private/path/trace-compose.env ps
```

The image runs as UID 10001 with capabilities dropped, includes native PDF dependencies and collected static assets, and copies only allowed source directories. No database, upload, backup, `.env`, development output or host virtualenv is copied into it. Volume ownership must match UID 10001 if substituting a bind mount. Do not run `down --volumes` on a real installation.

The dedicated bridge is `172.30.86.0/29`, with gateway/proxy `172.30.86.1` and application `172.30.86.2`. Check for network conflicts and adapt both Compose IPAM and `TRACE_PROXY_IP` together. Docker Desktop/network arrangements can differ: identify the actual trusted peer and test HTTPS redirects through your proxy; never replace its address with `*`. `TRACE_PUBLISH_IP` and `TRACE_PUBLISH_PORT` deliberately control host publication; the defaults are loopback and port 8000. A LAN proxy does not require widening the application's host publication.

### Self-contained Compose HTTPS option

To use a local proxy container instead of host nginx, copy `deploy/compose-https.env.example` to your protected environment file. Supply the real hostname/origin, secret, and an absolute private TLS directory containing `trace.crt` and `trace.key`; keep its private key mode `0600`. Clients must trust the issuing private CA. Set `TRACE_PROXY_IP=172.30.86.3` for this profile, rather than the host gateway used by the host-proxy option.

After the one-time migration/administrator commands above:

```sh
docker compose --env-file PRIVATE_ENV --profile https up -d --no-build
```

The application and nginx run on the same private bridge, and HTTPS publishes only at `https://localhost:8443` by default. For a real private hostname, adjust DNS/certificate, `TRACE_PROXY_SERVER_NAME`, allowed hosts and the HTTPS origin together. LAN publication requires explicit `TRACE_HTTPS_PUBLISH_IP`; it does not require publishing the backend beyond loopback. The proxy mounts configuration and certificates read-only and receives no database/evidence volume. It uses a minimal access-log format without request URLs/query strings. The profile depends on application readiness and requires no host nginx or external network service.

Use `--profile https` for subsequent proxy lifecycle commands. On the preparation machine, pull and record the verified nginx image digest, and transfer that image with the application image for offline use. Both images must already be loaded before using `--pull never` on an isolated server. The supplied profile is tested with a locally trusted temporary certificate; deployment certificates remain operator-supplied.

## Offline installation

Prepare on a connected machine matching the target **Python 3.13, operating system, CPU architecture and Linux ABI**:

```sh
python3.13 -m venv prep-venv
. prep-venv/bin/activate
python scripts/prepare_offline.py --directory wheelhouse
# Add --postgres and/or --test when those optional dependencies are needed.
python scripts/vendor_assets.py --check
python scripts/verify_wheels.py wheelhouse
```

The preparation script downloads binary wheels only for the fully pinned transitive requirements. Keep the generated `SHA256SUMS.json` separately trusted; hashes supplied alongside tampered artifacts are not signatures. Transfer the complete reviewed release, wheelhouse, Python runtime/venv support and the OS's signed PDF/font dependencies. Wheels do not supply Pango or a Python interpreter. For Debian, prepare `.deb` packages and their dependencies on a matching clean Debian 13 system (`apt-get --download-only install` for the Linux packages listed above); transfer the package cache or an approved signed offline repository and install it with the distribution package manager. Do not mix distribution releases or architectures.

On the isolated target, with those OS prerequisites installed:

```sh
umask 077
python3.13 -m venv .venv
. .venv/bin/activate
python scripts/verify_wheels.py /media/transfer/wheelhouse
python -m pip install --no-index --find-links /media/transfer/wheelhouse -r requirements/runtime.txt
python -m pip check
python scripts/vendor_assets.py --check
```

Then use the native initialization/production commands above. No package downloads, font services or runtime network access are required. For optional PostgreSQL use `requirements/postgres.txt` and a wheelhouse prepared with `--postgres`; for tests use `requirements/test.txt` and `--test`.

For offline Docker, build and test the image on a connected compatible host, then transfer the completed image rather than trying to run `apt` or `pip` on the isolated server:

```sh
docker save trace-local:0.1.0 -o trace-image.tar
# If using the HTTPS profile, also pull/save/load its reviewed nginx image.
# Transfer the image plus a separately verified checksum and release configuration.
docker load -i trace-image.tar
docker compose --env-file /private/path/trace-compose.env up -d --no-build --pull never
```

Run the one-time migration/admin commands with the loaded image before startup. Pin the verified image digest or retain its immutable image ID in your release inventory. The Dockerfile's Python minor/base OS can be overridden with `PYTHON_IMAGE` at build time; every rebuilt image must be reviewed and retested.

See [operations and recovery](operations.md) for backups, restore, health, restart and updates, and [PostgreSQL](postgresql.md) for the optional database path.

## Release tooling and resource defaults

Optional `requirements/quality.txt` pins lint/type/security tools; it is not needed at runtime. Prepare its wheels with `python scripts/prepare_offline.py --quality --directory NEW_WHEEL_DIRECTORY` on a matching connected machine. Advisory queries need internet access; ordinary tests, rendering and local assets do not.

Waitress limits connections to 32 and headers to 16 KiB; nginx examples additionally cap connections, body/header/idle time and request rates. Adjust these together with upload/report limits for the intended team workload. Compose uses read-only application/proxy roots and bounded noexec temporary mounts; private storage remains writable only on the dedicated volume. Core dumps are disabled. Large concurrent uploads may exhaust the bounded proxy/application temporary space and fail safely; provision and test limits deliberately. TRACE now enforces evidence quotas and available-space reserves; see [storage controls](storage-controls.md). Use host quotas and monitoring to bound reports, backups, proxy buffers and unrelated writers as well.

The native `scripts/serve.py --development` path serves bundled static assets through Django’s development static handler. This is restricted to loopback development; production continues to use collected local assets through WhiteNoise and never publishes private storage.
